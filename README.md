# publicservice — ระบบคะแนนพฤติกรรมนักเรียน

ตัด/เพิ่มคะแนนพฤติกรรมนักเรียน ป.1–6 โรงเรียนบ้านป่าเด็ง ผลส่งไป **กิจกรรมเพื่อสังคมและสาธารณประโยชน์** ใน ปพ.6 ของระบบรายงานผลการเรียน (students-report) อัตโนมัติ

## กติกา
- เริ่มภาคเรียนละ 100 คะแนน (นับแยกภาค 1 / ภาค 2) ตัดหรือเพิ่มได้ ไม่เกิน 100 ไม่ต่ำกว่า 0 (ไล่ตามลำดับที่บันทึก — เพิ่มตอนเต็ม 100 ไม่สะสม)
- ต่ำกว่า 50 คะแนน → กิจกรรมเพื่อสังคมฯ ภาคนั้น "มผ" (ช่องจุดประสงค์ `act_social_o1/o2`) — students-report คำนวณสดจาก `ps_behavior_records` ใน `assessmentsFor` (ไม่เขียนลง gr_assessments) ผลทั้งปีไม่ผ่านถ้าไม่ผ่านภาคใดภาคหนึ่ง
- สิทธิ์: ครูประจำชั้น (gr_homerooms ของระบบรายงานผลฯ) = เห็น/บันทึกเฉพาะห้องของตน · ครูฝ่ายปกครอง = ทุกห้อง + หน้าภาพรวมทั้งโรงเรียน (`/api/overview`)
- ครูฝ่ายปกครอง = ครูฝ่ายบริหารทั่วไปทุกคนอัตโนมัติ (`personnel_records.departments` มี `general`, status active, ยังปฏิบัติงาน) + ที่ superadmin/executive กำหนดเพิ่มใน ps_staff_roles + superadmin/executive
- เข้าจาก system เมนู ฝ่ายทั่วไป › รายงานพฤติกรรม ได้โดยไม่ต้องล็อกอินซ้ำ: system `/api/publicservice-sso` ออกรหัสใช้ครั้งเดียว 60 วินาที (`publicservice_sso_codes`) → `/sso?code=` ที่นี่แลกเป็น session
- หน้าเว็บเป็นแอปมือถือ (แถบนำทางล่าง, bottom sheet, ติดตั้งเป็น PWA ได้ผ่าน manifest.webmanifest) จอกว้างเปลี่ยนเป็นแถบนำทางซ้าย
- ยกเลิกรายการต้องมีเหตุผล (ผู้บันทึกเอง หรือฝ่ายปกครอง/ผู้ดูแล) รายการไม่ถูกลบ ประวัติอยู่ใน ps_audit
- ตัดคะแนนเรื่องเดียวกัน (เหตุผลเดียวกัน) ได้วันละครั้งต่อนักเรียน นับรวมทุกครู ตามวันที่เกิดเหตุ (เวลาไทย) · ยกเลิกรายการแล้วตัดใหม่ได้ · การเพิ่มคะแนนไม่จำกัด
- ตักเตือนก่อนตัดคะแนน: เรื่องเดียวกันต้องถูกตักเตือนครบ N ครั้งในภาคเรียน (ค่าเริ่มต้น 2, ตั้ง 0–10 ได้ที่หน้าบัญชี `ps_settings.warn_count`, 0 = ตัดได้ทันที) — กด "ตัดคะแนน" ตอนยังเตือนไม่ครบ ระบบบันทึกเป็นตักเตือนใน `ps_behavior_warnings` (ไม่มีคะแนน ไม่กระทบ ปพ.6) · ตักเตือน/ตัดเรื่องเดียวกันได้รวมวันละครั้ง · ยกเลิกการตักเตือนได้เหมือนรายการคะแนน
- โซนความรุนแรงตามคะแนนที่หักต่อครั้ง: เล็กน้อย 1–5 · ปานกลาง 6–9 · รุนแรง 10–15 · รุนแรงมาก 16+ (เกณฑ์แก้ได้ที่หน้าบัญชี `ps_settings.zones`) · โซนปานกลางขึ้นไป (≥ mid) ครูต้องเลือกเองตอนบันทึกว่าจะ "ตักเตือน" หรือ "ตัดคะแนนเลย" (`mode`) · กฎตักเตือนครบ N ครั้งใช้เฉพาะโซนเล็กน้อย
- การตั้งค่าทั้งหมด (เวลาเปิดบันทึก ตักเตือน โซน ข้อพฤติกรรมที่ตัดคะแนน `ps_settings.presets_deduct`) แก้ได้เฉพาะผู้ดูแลระบบ/ผู้บริหาร ครูอื่นดูได้อย่างเดียว
- ส่งต่อฝ่ายปกครองพิจารณา (`ps_referrals`): ครูที่ไม่ใช่ฝ่ายปกครองตัดคะแนนตั้งแต่ 10 คะแนนขึ้นไป (`ps_settings.refer_min` แก้ได้ที่หน้าบัญชี) ระบบส่งต่ออัตโนมัติ · ต่ำกว่านั้นครูประจำชั้นตัดคะแนนเองทันที (ไม่มีตัวเลือกส่งต่อ) · ยังไม่หักคะแนนจนกว่าครูฝ่ายปกครองกด หักคะแนน / ตักเตือน / ไม่ดำเนินการ (ต้องมีเหตุผล) ที่แท็บ "ส่งต่อ" · บันทึกชื่อครูผู้ส่ง (`referred_by`) และครูฝ่ายปกครองผู้กด (`decided_by` = ผู้บันทึกรายการคะแนน) · ใช้กติกาเดิม: เรื่องเดียวกันวันละครั้ง (นับเรื่องที่รอพิจารณาด้วย) โซนเล็กน้อยต้องตักเตือนครบก่อน เปิดเฉพาะเวลาบันทึก · ผู้ส่งยกเลิกการส่งต่อได้ระหว่างรอ · ครูฝ่ายปกครองบันทึกเองไม่ต้องส่งต่อ
- เพิ่มคะแนนได้เฉพาะครูฝ่ายปกครอง: ครูประจำชั้นกด "+ ความดี" = บันทึกความดี (ประเภทตาม system) ลง `good_deeds` (ตารางเดียวกับบันทึกความดีใน system — ซิงค์สองทาง) แล้วรอฝ่ายปกครองอนุมัติที่แท็บ ส่งต่อ › ความดีรออนุมัติ · อนุมัติ = เพิ่มคะแนนตามประเภท (`ps_settings.merit_points` แก้ได้ที่หน้าบัญชี) บันทึกใน `ps_merit_reviews` + `good_deeds.ps_record_id` · ไม่อนุมัติ (ต้องมีเหตุผล) = ยังเป็นบันทึกความดี · ครูฝ่ายปกครองบันทึกความดีเอง = เพิ่มคะแนนทันที · ความดีที่บันทึกใน system ก็ขึ้นมารออนุมัติที่นี่ (system ปิดปุ่ม +1 ของบันทึกความดีแล้ว)
- บันทึก (ตัด/เพิ่ม) ได้เฉพาะ จ.–ศ. ในเวลาที่ตั้งไว้ (ค่าเริ่มต้น 08:30–16:30 น.) ผู้ดูแลระบบ/ผู้บริหารแก้ได้ที่หน้าบัญชี (`ps_settings`)

## สถาปัตยกรรม
- Cloudflare Worker `publicservice` + static assets (`public/`), D1 `banpadeng_school_db` ร่วมกับ school-db / students-report, บัญชีจากตาราง `users`
- ตาราง `ps_*` สร้างเองเมื่อเรียก API ครั้งแรก (`src/lib/schema.js`)
- `src/lib/crypto.js`, `src/lib/auth-sessions.js` สำเนาจาก students-report · `src/lib/roster.js` คัดลอกตรรกะรายชื่อ/เลขที่จาก students-report (แก้ที่นั่นต้องแก้ที่นี่)
- สูตรคะแนน: `foldScore` (src/lib/schema.js) ต้องตรงกับ `behaviorScores` ใน students-report/src/lib/data.js

## ติดตั้ง
1. เชื่อม repo กับ Cloudflare Workers (หรือ `npx wrangler deploy`) — โดเมน `publicservice.banpadengschool.ac.th` ตั้งไว้ใน wrangler.jsonc
2. ตั้ง secret `JWT_SECRET` ให้ค่าเดียวกับ school-db/students-report (ถ้าเปิด Turnstile ให้ตั้ง `TURNSTILE_SECRET_KEY` และเพิ่มโดเมนนี้ใน widget ของ Turnstile)
3. ตรวจ `/api/health`

## Face ID / Passkey — Patch 1.2

เข้าสู่ระบบด้วยรหัสผ่านเดิม แล้วเปิด **ตั้งค่า Passkey** เพื่อเพิ่มอุปกรณ์ ครั้งต่อไปกด **Face ID / Passkey** ได้ รหัสผ่านเดิมยังใช้สำรองได้ บัญชีโรงเรียนใช้ Passkey ร่วมกันระหว่าง system, grades, teachingmedia, activity และ publicservice บนโดเมนโรงเรียน

รัน `npm ci` ก่อนทดสอบ/build ตาราง Passkey สร้างแบบ additive ในคำขอแรก ใช้ HTTPS; ไม่มีการเก็บภาพใบหน้า ลายนิ้วมือ หรือ private key

[รายละเอียด วิธีใช้ ขอบเขต และผลตรวจสอบ](https://github.com/SATTASAI/banpadeng-school-db/blob/main/docs/passkeys.md)
